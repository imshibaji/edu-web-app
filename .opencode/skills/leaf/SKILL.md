# Larnr — Leaf 5 Application Guide

Larnr is a tutor-booking marketplace. **Leaf 5 MVC** backend (`app/`), **Inertia + React + TypeScript** frontend (`app/views/js/`), **Tailwind CSS v4 + daisyUI 5** (`themes: false`, single custom `larnr` dark theme), **SQLite** database. Money is stored as **integer cents** in a `currency` column per row.

Before editing code, read `.leaf/CONTEXT.md` if it exists (Leaf's shared agent memory). After finishing meaningful work, add a `Recent Changes` entry there (newest first, max 5).

## Commands (verify after every change)

```bash
npm run build          # frontend production build (the app's only "typecheck"; grep output for errors)
npm run dev            # vite dev server (hot reload)
php leaf serve         # start the PHP dev server
php leaf app:init      # migrate app/database/*.yml via Leaf Schema (idempotent; also: db:migrate)
php leaf app:seed      # seed demo data from the yml seed blocks (also: db:seed)
php -l <file>          # PHP lint before finishing
```

There is **no automated test suite**. Verification = `npm run build` passing + `php -l` clean + manual flow check.

## Routing

- Route partials in `app/routes/` starting with `_` are auto-loaded. Add routes to `_app.php` (public) or `_auth.php` (auth/admin/tutor).
- MVC syntax — controllers by string, no closures for pages: `app()->get('/users', 'Auth\admin\UsersController@index');`
- `response()->inertia('path/to/page', $props)` — page name maps to `app/views/js/pages/<path>/to/page.tsx`. Admin pages use `'admin/...'`.
- Redirects after POST **must use 303**: `response()->withFlash('success', 'msg')->redirect('/admin/currencies', 303);` (prevents Inertia method re-use).
- `response()->redirect()` calls `exit()` by default — a preceding `return` is style only.
- Auth guards live in two layers: route middleware (`'middleware' => 'auth.required'` on groups) AND a controller-level `requireAdmin()` check at the top of every admin method.

## Controllers

- Extend the base classes, never `Leaf\Controller` directly:
  - Public/Tutor/enquiry → `App\Controllers\Controller`
  - Auth/admin/profile → `App\Controllers\Auth\Controller`
- **`auth()->user()` returns a Leaf Auth wrapper whose `__call()` never throws** — role checks on it are unreliable. Use `$this->authUser()` (base `Controller`) to resolve the real Eloquent `User`, or the role constants `User::ROLE_ADMIN / ROLE_TUTOR / ROLE_STUDENT`.
- Admin methods start with `if (!($user = $this->requireAdmin())) return;` then use `$user->id` for activity logging.
- Keep controllers thin: reuse `paginate($query, $perPage)` (Auth base) and the shared `tutorListingData($request)`.
- Read input with `request()->get('field')` — works for GET/POST/JSON (Inertia payloads).

## Models (Eloquent)

- Extend `App\Models\Model`. Eloquent-like API: `User::query()->where(...)->get()`, `with(['tutorProfile'])`, relationships, `orWhereHas`, `pluck`, `groupBy`.
- The `Currency` model is different — it uses `\Illuminate\Database\Capsule\Manager::table('currency_settings')` directly and auto-creates its table via `Currency::ensureTable()` with a fallback to `FALLBACK_RATES`.
- Money: `hourly_rate`, `rate_cents`, `amount` are integer minor units; convert with `Currency::convert($cents, $from, $to)` or frontend `displayAmount()`.

## Frontend / Inertia

- Page resolution: `app.tsx` resolves `./pages/${name}.tsx` from the `inertia()` string. Moving a page means updating the controller string too (e.g. dashboard → `admin/dashboard`).
- `useForm().post('/url')` sends `data` as the JSON request body; second arg is Inertia options only. For a standalone payload use `router.post('/url', payload, options)`.
- Flash toasts: backend sets `withFlash('success'|'error'|'errors', ...)`; frontend reads via `flash-toast.tsx` / page props (`errors`).
- Admin pages use the `AdminLayout` sidebar component (`components/larnr/admin-layout.tsx`) with a `section` key matching the sidebar item. Add new admin sections to its `SECTIONS` array.
- UI conventions: daisyUI classes, `font-display` headings, `card card-border border-base-content/10 bg-base-content/4` card style, `btn btn-primary btn-sm rounded-full` buttons, rounded-xl inputs.

## Currency system (touch carefully)

- **Base currency is dynamic** (stored in `currency_settings.is_base`), defaults to INR (rate 1.0). All stored rates are relative to the base.
- `app/models/Currency.php` — `allSettings()`, `getBaseCurrency()`, `addCurrency()`, `updateRates()`, `setBaseCurrency()`, `removeCurrency()`. `currency_settings.code` is the primary key — every write must be idempotent (`updateOrInsert`), never a bare `insert()`.
- Frontend `app/views/js/utils/currency.ts` — dynamic `CurrencyMeta` list loaded from `/api/currency-rates` (`loadRatesFromAPI()` at app init). `displayAmount(cents, sourceCurrency, auth)` converts from the **row's stored currency**, never from the display/cookie currency.
- **`displayAmount()` must take the tutor's actual `currency` as source** — the `lnr_currency` cookie is only the *target*. Using the cookie as source was a past conversion bug.
- Base currency change resets the new base rate to 1.0 and clears the cache; existing stored rates are treated as already-relative and are not rewritten.

## Validation — Leaf Form (footguns verified in vendor source)

`request()->validate([...])` returns the validated array on success, **`false` on failure** (NOT an error object). Always guard: `if (!$data) { redirect back with errors }`.

Rules: `string` (free text), `text` (letters+spaces only), `numeric`, `email`, `boolean`, `in:[a,b]`, `between:[min,max]`, `array`, `optional`. **There is no `required` rule** — fields are implicitly required (empty/null/`[]` fails unless `optional`).

**Known limitations (read before writing validation):**

1. **Nested-array wildcard rules don't work.** `'rates.*.rate' => 'numeric'` ALWAYS fails — Leaf resolves the `*` as a literal key via `Anchor::deepGetDot`, finds nothing, and reports the field "required". For arrays, validate the parent with `'array'` and check each item manually in PHP, or read the body directly.
2. **`min:` / `max:` are string-LENGTH rules** (`/^.{s,}$/`), not numeric ranges. `min:0.000001` breaks for floats. Validate numeric bounds yourself: `(float) $v > 0`.
3. `optional` rules don't put the key in the returned array when absent — use `?? default`.

**Reliable pattern** (used by `UsersController::toggle`):
```php
$code = strtoupper(trim((string) request()->get('code', '')));
$rate = (float) request()->get('rate', 0);
if ($code === '' || $rate <= 0) { /* redirect back with error */ }
```
Delegate enforcement to the model (`Currency::addCurrency()` already throws on `rate <= 0`).

## Auth

- Sessions-based (config/auth.php): `users.password_hash`, `unique: ['email']`. Auth middleware overridden in `_auth.php` (`auth.required` → `/auth/login`, `auth.guest` → `/dashboard`).
- Roles via `User::isAdmin()`, `isTutor()`, `isStudent()` on the real model.
- Log activity after mutating actions: `UserActivity::log($user->id, UserActivity::TYPE_ACCOUNT_UPDATED, 'description');`
- Seeded accounts: `admin@larnr.app` (ADMIN), `demo@larnr.app` (STUDENT), tutorN@larnr.app — password `password`.

## Database / schema

- **Source of truth: `app/database/*.yml` (Leaf Schema)** — one YAML file per table, each with `columns:` and optional `seeds:`. `php leaf app:init` (or `db:migrate`) migrates all files; `php leaf app:seed` (or `db:seed`) runs all seed blocks.
- **Fresh setup:** `php leaf app:init` → `php leaf app:seed`. **Existing DB:** `db:migrate` "adopts" existing tables as baseline without altering them (no data loss); only run seeds on a fresh DB.
- **UUID PKs:** `increments: false` at top level + `id: {type: uuid, primary: true}` (SQLite → `varchar` PK). Do NOT use `increments: true` (auto-increment int id) for this app.
- **Not expressible in this vendored Leaf Schema:** FK constraints (`foreign`/`foreignTable`/`foreignColumn`/`onDelete` column attrs are parsed but never applied), composite primary keys (tutor_subjects), composite indexes, and CHECK constraints. Compensate at the app layer — e.g. `SubjectsController::delete()` deletes `tutor_subjects` rows explicitly.
- **`db:seed` seeds EVERY yml file.** Files without seed data MUST declare `seeds: count: 0` — otherwise Leaf falls back to `Model::__seeder()` and fatals.
- **Seed tokens:** `@hash("password")` → `Password::hash()`; `@tick.add(1, "day").set("hour", 13).set("minute", 0).set("second", 0).format("YYYY-MM-DD HH:mm:ss")`; `@faker.*`, `@randomString(n)`. Cross-table seed rows use deterministic UUIDs so references (tutor_subjects, slots, activities) resolve.
- **Adding a table:** add `app/database/<table>.yml`, add a matching Eloquent model, then run `app:init`. Existing DBs adopt it as baseline; fresh DBs create it.
- Don't mix `db()` (Leaf query builder) and Eloquent in one transaction — prefer Eloquent models everywhere.
